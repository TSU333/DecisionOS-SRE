# 第八轮故障分类专项强化协议

execution_scope: mvp。第七轮是已完成的轻量基线诊断，本轮编号为8。新协议在训练前固定，详见 outputs/round8/protocol.json。

当前验证集根因40/40正确、故障37/40正确；训练损失远低于验证损失。基于这一开发证据，固定共享主干、根因文本打分器及根因数值分支，只续训故障文本头、全局数值故障头和预测根因加权的局部故障头。仍不输入正确根因。

六个固定实验：数值故障隐藏层Dropout为0 / 0.15 / 0.30，各自配合故障标签平滑0 / 0.05；全部seed45、lr0.0001、batch16、weight_decay0.01，最多2200更新，60个无改进epoch早停。主干和输入不变，可以缓存精确表示；Dropout仅在训练开启，导出后无运行时结构变化。标签平滑只应用五类故障，根因候选padding不会进入平滑目标。

沿用原400个案例与所有划分：165训练、40验证、40校准、85门控、历史回归15+25+30。指标temporal-v1、2048 token预算、一次共享编码均不变，本轮不使用调用链；没有新独立测试。原始输入文件与父模型准备数据哈希相同。

选择顺序保留原规则：OB验证联合≥95%、SS≥90%，再依次比较四cohort联合均值、总体联合、sum NLL，现任模型参与比较。所有模型选择仅使用训练/验证；冻结后只验收一个获选候选。新增发布保护：任何历史回归cohort根因/故障/联合准确率下降则保留现任，不再尝试次优候选，也不依据回归修改参数。这是旧案例回归保护，不是新的泛化确认。

校准、门控仍只使用各自划分；门控经验风险≤5%、至少接受30条。重复使用门控及验证集存在选择偏差。90%根因/90%故障/85%联合仍是此前工作假设，非用户原Prompt明确指标；不宣称生产自动接受安全，不执行运维动作。

验收包括冻结分支权重与logits不变、推理关闭Dropout、标签缺失和候选mask、训练ID隔离、缓存/完整推理一致、源码与checkpoint绑定、CPU重载、真实HTTP、回归、消融及CPU性能。未改进则如实记录负结果并保留旧模型。
