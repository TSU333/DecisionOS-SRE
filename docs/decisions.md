# 工程选择记录

1. 新建本地 Git 仓库；机器 PATH 无 Git，通过 dulwich 初始化与提交。未创建远程仓库，因为用户未指定远程平台或组织。
2. 原 E 盘写操作返回 WinError 433。经目录级读写授权转到 D:\CODEX\DecisionOS-SRE；未修改任何 ACL 或关闭安全机制。
3. 系统 Python 3.13 无 ML 依赖。使用仓库内 venv，固定 torch 2.7.1/cu128、transformers 4.51.3 及 pyproject 版本；完整解析版本另存 lock。
4. 选择官方转为 Parquet 的 RE1-OB 125 例；先下载 29.5 KB 索引并检查一例，再下载最小完整单应用子集。排除 research/deployment 范围。
5. 不猜测单位；Parquet 字段无单位元数据时明确 source_unit_unspecified。原始列名和数值均保留。缺失值不做回填。
6. 遥测列名最后一个下划线分隔服务与指标；该规则经真实列验证。候选包含主机/聚合项等实际遥测实体，即便它们从未成为本数据集注入标签。不会依据 gold 删减候选。
7. 原始 case/绝对采集时间可能编码故障类型。模型文本只使用相对窗口定义与观测汇总；绝对 decision_time 仅用于输入因果校验，不进入 encoder。
8. 一个 run 一个固定窗口；原始/基线/归一化四舍五入窗口指纹用于保守重复分组。公开来源未给出更完整实验谱系，因此不承诺已证明所有重复采集独立。
9. 采用固定五路小规模 holdout，保持部署 checkpoint、校准器和策略对应。15 例校准只支持探索性拟合；阈值按至少 30 独立组和 joint error <=5% 搜索。无可行阈值即全 REVIEW，不降低门槛。
10. 使用 PyTorch SDPA，关闭 ModernBERT reference_compile，无 FlashAttention 依赖。训练允许 CUDA autocast BF16、梯度检查点；CPU 始终 FP32。
11. 初始 max_length=2048。完整保留候选，按观测变化绝对值排序压缩 metrics，记录每例保留率。没有训练拟合的预处理；基线来自本 incident 决策前已观测的正常窗口。
12. 仅两轮、固定 seed 42、相同数据与增强预算比较 frozen 与 SFT。训练样本不足以得出广泛质量结论。类别在 train 按 fault 分层均衡，不使用额外类权重。
13. scalars 温度拟合使用 scipy 有界优化 logT in [-3,3]。联合 routing score 为两个 confidence 的 min，不称为联合校准概率。
14. checkpoint SHA、tokenizer SHA、split hash、ontology/serializer/max_length hash 绑定校准器与策略。API 无有效接受条件时拒绝自动接受。


## 第二轮训练决策

- 保持 MVP、原 50/15/15/30/15 分组与所有历史模型。原测试已经看过，改称本轮回归集合，不把它用于选参；不新增伪独立窗口。
- 从每头验证损失和小样本诊断判断故障分类是瓶颈。分组学习率、学习率预热与线性衰减、更多更新与关闭整段证据 dropout 改善训练条件。
- v2 按可观测遥测签名排序并生成别名，移除服务名称依赖；单位在共享说明中保留，数值仍来自因果摘要。均值池化让故障头读取全序列输出。训练/验证样本全部指标保留，平均输入约1200 token。
- 数值残差 MLP 是显式对照，仍共享一次编码；只使用 token 内保留的证据。保留了故障更强但其他指标较差的结果，没有预设复杂方案必胜。
- 按预先固定的验证 NLL 选择 canonical SFT（0.6224），而非冻结数值融合（0.6978）；冻结对照的验证联合准确率更高，这是概率损失与 argmax 准确率的取舍。回归评测之后不再改选。
- 最终校准和门控均使用 CPU，匹配实际 API；风险目标5%、最低接受30条不变。没有可行门槛，全部 REVIEW。
- 最终测试、真实 API、reload、CPU benchmark 均成功；更强的独立泛化结论仍需要新数据与多 seed。完整状态见 outputs/retrain/status.json。


## 第十轮：应用专属故障分类头

- 保持MVP、原始run划分与五类故障定义。当前同应用可用400例已全部使用，本轮不把重复抽样、窗口或视图计为新独立案例。
- 用原本已可观测的application字段路由两个小型故障头，验证应用间共用参数是否影响效果。映射从TRAIN公开输入获得并写入pipeline绑定，数据集编号与gold不进入路由。
- 从第五轮精确复制文本/全局数值/根因条件故障头，冻结共享主干、根因和共享回退头。未知应用复用旧共享头并强制REVIEW。分支以张量索引选择，避免临时替换模块带来的并发状态问题；每incident仍只编码一次。
- 采用共享头对照、应用头、较小学习率应用头及dropout应用头四组固定实验；全部只抽样164条有效TRAIN，不使用上轮增强视图。有效训练样本少，不扩大主干或引入新的依赖。
- 配置和预算训练前封存，先完成全部训练，再根据40条验证选择一次。历史回归只作为预先固定的退化保护，失败不改选次优模型。准确率工作目标并非用户原Prompt明确数值；不把反复使用的验证/回归作为新的独立确认。
- 新模型仅在验证改善且三个历史cohort根因、故障、联合均不下降，并完成CPU重载、HTTP、依赖和权重审计后才允许改默认指针。协议见round10_protocol.md，执行结果见round10_results.md。


## 第十一轮：有限共享编码器微调

- 验证侧剩余错误集中在网络延迟/丢包和磁盘/CPU、内存混淆；主干较早仅在较小OB数据上微调。此前分类头方案未通过验收，因此本轮比较真实编码器末层更新与文本故障头对照，不预设主干更新一定有效。
- 冻结全部数值分支及文本根因scorer，允许最后2/4层和final_norm更新。根因logits仍会随共享表示变化，因此发布仍保护根因、故障、联合三项，而不宣称根因输出固定。
- 在最长有效TRAIN输入上做3步诊断后丢弃权重，以实测显存和速度确定micro batch1、累积4、最多6个epoch。固定三组seed48，编码器lr1e-5、故障文本头lr3e-4；3轮无改善早停。两层/四层方案需要完整前向和反向，不能复用冻结表示缓存。
- 保留原400案例分组，164个有效TRAIN，无数据增强、无新独立案例、无新增依赖。校准和门控仍用独立指定分区；未知应用强制REVIEW，运维动作关闭。
- 全部源码和协议显式暂存、提交并逐哈希核查后才开始训练。最佳epoch只保存可训练张量，最终恢复验证一致后导出完整权重；实际更新与被冻结参数逐一核验。
- 三组验证均不胜出现任时跳过候选历史回归；有胜出时只检验一个预先封存候选。失败后不改选次优模型、不以回归结果继续调参。具体协议及真实结果分别见round11_protocol.md和round11_results.md。


## 第十二轮：因果动态摘要与匹配对照

- TRAIN审计发现部分原变化z触及±100截断，新增幅度分位数与局部波动摘要作为可证伪假设。只使用本run既定决策前窗口，不用gold、不拟合跨案例预处理；先封存公式再处理所有split，400例原输入与旧数值前缀逐项保持一致。
- 按新版本扩展数值输入120→190、全局360→570，用零列迁移保留初始化预测。原版本继续忽略新字段。动态证据缺失在新版本明确REVIEW，API不计算未来信息、不接收gold。
- 保持共享编码器冻结，比较旧特征故障头、新特征故障头、dropout和联合头4组。相同seed49、lr1e-4、batch16、最多2200步、80轮早停、cohort均衡；配置、源码、协议训练前提交。缓存与完整推理逐例核对，实际更新和新增列训练后核验。
- 原始400案例不变，有效TRAIN164；无视图、无独立新增数据。只按40验证选一个模型，胜出才打开历史回归；三组根因/故障/联合不得退步，否则保留现任。即使旧特征对照进步，也不能归功于新增动态特征。
- 额外真实HTTP只用验证输入检查新特征边界，不拟合校准/门控，不用于模型选择；缺少产物强制REVIEW。数据准备脚本另提供新输出目录以便按同一公式重建，不覆盖封存文件。完整协议与真实结果见round12_protocol.md和round12_results.md。


## 第十三轮：分组CV和新案例准入

- 针对多轮小验证集改善而回归退步，建立TRAIN内3折×3seed，两种固定特征方案。原始run/重复组不可交叉；每折另设inner-stop，outer不选epoch。不将开发CV当作独立泛化确认，不改原七路分区。
- 原始公开预训练主干保持冻结，分类头每折重新初始化；第五轮及后续已见全TRAIN的工件不得用于CV起点。两特征方案配对旧头初值，新列补零；初值、来源哈希与冻结主干实际核验。
- 固定lr3e-4、dropout.15、batch16、最多160轮/1000步、25轮早停。该预算用于从头训练，不套用旧暖启动22步结论。每个seed有164条OOF，不把3seed的492次重复预测当独立病例。
- 所有原始标签只做来源一致性核对；反复出错进入复核清单，不自动改gold。外部数据在任何预测前先固定版本、审计采样与语义，元数据_id与遥测明确分开。
- OpenNetAI来源94条事件已下载审计，但分钟级采样与当前60秒观察预算不相容，准入0；不插值伪造观测或偷偷延长窗口。RCAEval当前兼容case仍400，无新增。补充需求和可复现下载清单已保存，不进行生产注入。
- 18次训练和97项测试通过，动态摘要平均联合提升约3.46个百分点但seed波动更大，保留第五轮默认，不据CV做发布。CPU重建和文件/抽样审计本轮执行，API与延迟沿用既有证据并明确未重测。
